# Model card: `ridge-floor`: ridge floor-occupancy baseline

| field | value |
| --- | --- |
| family | shallow-learned (closed-form ridge regression) |
| version | 1.0.0 |
| status | available (scenario-B geometry only) |
| preprocessing | pp-1.0.0 |
| weights | `models/baselines/ridge_floor/weights.json` (`RidgeWeights`, `packages/engine/src/recon/ridge.ts`) |
| training | `models/baselines/ridge_floor/train.py`, metrics in `metrics.json` |
| dataset | `synthetic-ridge-v1` (`datasets/manifests/synthetic-ridge-v1.json`) |

## Intended use

A learned baseline that any heavier model must beat, and a working example of the model
contract: fixed geometry, declared normalization, out-of-distribution check, explicit refusal
outside its domain. Not intended for real deployments.

## Inputs and outputs

- Input: 56 features per frame, `[deltaRssDb[28], motionEnergy[28]]` in `buildLinks` order for the
  8 transceivers of scenario B. NaN (no packet on a link this frame) is replaced by the training
  mean; features are standardized with the training mean and standard deviation.
- Output: one score per 0.5 m floor cell (12 × 10, x fastest), `clip(z·W + b, 0, 1)`. The engine
  extrudes it to voxels below 1.8 m; there is no vertical information.

## Training data and procedure

- 48 synthetic scenes of 16 s generated by the Python reference simulator and pipeline in the
  fixed scenario-B room (6.00 × 5.00 × 2.80 m, 8 perimeter nodes, B's furniture, signal and
  impairment settings): 6 empty, 24 with one subject, 18 with two subjects. Subjects follow random
  waypoints (0.5-1.4 m/s) with stops, sits and turns; random start delays add empty-room segments.
  The first 5 frames of each scene are dropped (filter warm-up): 7,440 frames at 10 Hz.
- Target: a cell is 1 when its centre is within subject radius + 0.25 m of a present subject.
- Split by scene seed, stratified by scene kind: 32 / 8 / 8 scenes (4,960 / 1,240 / 1,240 frames).
  No frames of one scene appear in two splits.
- α chosen from {1e-2 … 1e5} together with a decision threshold on the validation scenes
  (maximum pooled IoU): α = 1, raw threshold 0.30. The validation curve is flat for α ≤ 100.
- Operating point: least-squares outputs for sparse 0/1 targets are shrunk towards the base rate.
  W and b are multiplied by 0.5 / 0.30 = 1.667 so the engine's 0.5 level equals the
  validation-chosen threshold. Scores are detection scores, not probabilities.
- OOD limit `oodMaxMeanAbsZ` = 1.6072: the 99.5th percentile of per-frame mean |z| on the
  validation frames. Above it the engine reports `degraded` (distribution shift) and still shows
  the output. On the test scenes 0.4 % of frames exceed it.
- Runtime: data generation dominates (≈ 60 s CPU per scene). 742 s wall time with 4 worker
  processes on an otherwise idle 4-core machine; 1,096 s for the run that produced the committed
  files, which shared the CPU with other jobs. Both runs produced the same dataset checksum.

## Evaluation (synthetic test scenes; not validated on real data)

Pooled over the 1,240 test frames, 0.5 m cells:

| model / threshold | IoU | precision | recall | median frame IoU |
| --- | --- | --- | --- | --- |
| **ridge-floor** @ 0.5 (validation operating point) | **0.407** | 0.515 | 0.660 | 0.400 |
| rti-bayes @ 0.5 | 0.246 | 0.259 | 0.833 | 0.267 |
| rti-bayes @ 0.6 (engine default `occupancyThreshold`) | 0.271 | 0.303 | 0.720 | 0.273 |
| rti-bayes @ 0.8 (threshold chosen on validation) | 0.290 | 0.404 | 0.507 | 0.286 |

By scene kind (IoU, ridge vs rti-bayes @ validation threshold): one subject 0.411 vs 0.333, two
subjects 0.404 vs 0.259. Neither model marks any cell in the 318 empty-room test frames.

rti-bayes numbers are the floor projection of the engine's 3-D output for the same runs (EMA 0.5
+ 3×3×3 box filter at 0.25 m, max over observed voxels and over the 2×2 voxel columns of each
cell). Unobserved voxels (variance ratio > 0.95) are excluded: rti-bayes reports 0.5 there, and
because the bottom and top voxel layers are entirely unobserved in this layout, including them
marks every cell occupied (IoU 0.023 at 0.5). Ridge is evaluated per frame without temporal
smoothing.

Reproduce: `python models/baselines/ridge_floor/train.py`; check the saved weights against the
recorded numbers: `python models/evaluation/evaluate.py`.

## Limitations

- Only the training geometry: any other room size or node layout fails the `geometryKey` check
  and the engine reports `unsupported`.
- Synthetic training and test data from the same simplified, uncalibrated channel model. The
  comparison with rti-bayes says nothing about real rooms, where multipath, people and hardware
  differ from the simulator.
- Linear in 56 features; it cannot represent interactions between links or separate close
  subjects. Train IoU (0.566) is well above test IoU (0.407), so more scene variety would help even
  within the simulator.
- In the engine, its blocky 0.5 m scores go through the same EMA and box filter as rti-bayes; the
  metrics above are computed before that smoothing.
